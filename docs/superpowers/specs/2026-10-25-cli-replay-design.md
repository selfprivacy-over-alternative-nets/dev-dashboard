# CLI replay along the setup diagram — design (FR88)

*2026-10-25 · design only, nothing built yet · owner: Akke · implements `flow_requirements.md` FR88.*

A small terminal box ("the player") rides the pipes of the chosen configuration in `flow.html` and shows,
at every point of its trajectory, what the real `./dash` install wizard printed at that moment. Dragging the
box back up the pipe rewinds; dragging it forward fast-forwards. Every frame comes from a **real recording of
one complete from-scratch run** of the real scripts; nothing is ever synthesised. The recording is tied to
the code by **step markers the scripts emit themselves**, and a pre-commit hook + CI **verify** that the
diagram's nodes and paths, the step markers in the scripts, and the committed recordings all agree.

This document is the result of three independent designs, seven adversarial verifications (with real
experiments: asciinema cast format, escape-sequence survey of every script, cast size from real install
logs, a Playwright drag prototype, GIF-vs-text comparison, marker/eval safety, toggle inheritance) and a
synthesis. Evidence is summarised in §12.

---

## 1. Decisions (the short version)

| Question | Decision | Why |
|---|---|---|
| Recording format | **asciicast v3 text** (`asciinema 3.2.1`, already in the nix store), replayed in the browser by a small hand-written terminal model. **No GIFs** in git. | A full wizard mock is ~45 MB as per-step GIFs vs ~10 KB gzipped as text; only text replay can scrub *backwards*; git/Pages stay text-only; `visualisation.md` already says CLI output may be stored as text and recreated. `agg` stays an optional dev convenience for README screenshots. |
| How recordings tie to code | Scripts print an **invisible OSC 9999 step marker** right before every prompt. A normaliser turns them into native asciicast `m` (marker) events. A **step index** generated by scanning the scripts is the canonical "CLI interface". | Verified: markers survive verbatim in the cast, are stripped from plain-text output, are ignored by terminals, and `agg`/`asciinema play` consume the native `m` events. |
| Overlay vs one level deeper | **Both, one engine, overlay first.** Phase 1: the player rides the existing `setup-map` pipes of the chosen toggles (the pipes *are* the wizard route). Phase 2: a child diagram `wizard` with one node per question, **inheriting the parent's toggles**, laid along a ghosted copy of the parent. | The overlay needs no new diagram and answers "where does this happen"; the deeper view is where per-question guidance and the strongest verifier check (every recorded question has a node) live. One route/trajectory mechanism serves both. |
| Concise vs literal text | A node stores a **concise label** plus a **step id**. The literal prompt is never copied into the diagram; it is looked up from the generated step index at render time and shown small under the label and in the hover tooltip, with `file:line` and the recorded answer. | The mapping (the id) is verified, not the wording. A reworded label can't break anything; a renamed or removed question breaks the commit. |
| "Updated when the code changes" | The step index, snapshots, verifier and stale flags **regenerate automatically** in the hook/CI. A recording whose step prompt changed is **flagged stale per step** (badge in the UI) and the exact re-record command is printed. CI `--strict` fails on stale recordings so `main` never silently carries one. Re-recording itself needs hardware (req 159) and stays a human step. | A pipeline cannot do a from-scratch hardware install; what it can do is make drift impossible to miss and impossible to publish unnoticed. |
| Per configuration | One recording per toggle triple `method·net·reach`, selected by the toggle bar. No recording → an **honest placeholder** in the player with the exact command to record one. | Never a frame that wasn't recorded. |
| Secrets | Raw casts stay git-ignored under `media/`. Only normalised, **redacted** casts are committed, and the verifier re-scans them (denylist, patterns, entropy, hidden-input assertion). | Real runs echo the Tailscale auth key, the box API token, MACs, IPs and the tailnet name. |

## 2. Architecture and data flow

```
real from-scratch run (laptop pty)                      committed (dev-dashboard, served by Pages)
──────────────────────────────────                      ─────────────────────────────────────────
./dash record-wizard --cast media/replays/raw/<ts>.cast
   └─ asciinema rec … -c './dash find-target …'
        ├─ dash: find-target prompts      ─┐
        ├─ tools/resolve_flake.sh          │ scripts print  \e]9999;sp-step=<ID>\e\  before each prompt
        ├─ tools/add-cloudflare.sh --plan  │ (stderr, invisible)           ┌────────────────────────────┐
        ├─ ./dash run install.…  (phase B) │                               │ docs/replays/steps.json    │◄── tools/replay_index.py
        ├─ tools/finish_box_setup.sh       │                               │  (scan of the scripts:     │    (static scan, deterministic)
        └─ tools/add-cloudflare.sh (apply) ┘                               │   id → file:line, prompt)  │
                     │ raw .cast (secrets!)                                └────────────┬───────────────┘
                     ▼                                                                  │ ids
   tools/replay_import.py  ── split markers → "m" events, redact, squash phase B ──►  docs/replays/wizard/<config>.cast
                                                                                        docs/replays/wizard/<config>.meta.json
                                                                                        docs/replays/wizard/index.json
                                                                                                   │
   docs/diagrams/setup-map.json  meta.replay.route (waypoints + step ids)  ◄── tools/replay_verify.py ──► fails commit/CI on
   docs/diagrams/wizard.json     nodes with step ids, rail pipes               misalignment, secrets, stale index, size
                                                                                                   │
   flow.html + replay.js  ── toggles → config → cast → markers → trajectory ──► player box, drag-to-scrub, autoplay
   docs/gen_flow_svg.py   ── same geometry, first frame of the default config, or the placeholder (static snapshot)
```

Three artefact classes, each with one writer:

1. **Scripts** (hand-written, with `sp_step` calls) → **`docs/replays/steps.json`** (generated by `tools/replay_index.py`; committed; verified byte-equal on every commit).
2. **Raw cast** (`media/replays/raw/…`, git-ignored) → **normalised cast + sidecar + index** under `docs/replays/wizard/` (generated by `tools/replay_import.py`; committed; verified idempotent).
3. **Diagram JSON** (hand/GUI/Claude-edited, deterministic dump) referencing step ids and route waypoints; verified against 1 and 2.

## 3. Data model additions (all round-trip through `serialize()` / `_dump` untouched: strings, booleans, integers, arrays only)

### 3.1 Diagram JSON

| Field | On | Meaning |
|---|---|---|
| `meta.replay.flow` | diagram | `"wizard"` — which step index / cast directory this diagram uses (`docs/replays/<flow>/`). |
| `meta.replay.keys` | diagram | `["method","net","reach"]` — toggle ids that form the configuration key. |
| `meta.replay.route` | diagram | Ordered waypoints: `{"at":"<nodeId>"}` or `{"along":"<edgeId>","rev":true?}`, each with `"steps":["A5","A6",…]` (step ids that happen there) and optional `showWhen` (existing `{toggleId:[values]}` shape) and `label` (guiding text shown while travelling). The trajectory is derived from this at render time; no coordinates are stored. |
| `meta.replay.player` | diagram | `{"w":520,"h":300}` integers (world px). Default when absent. |
| `meta.inheritToggles` | child diagram | `true` → the child has **no** `meta.toggles` of its own; it uses the parent's definition, and `showWhen` on its nodes/edges references the parent's toggle ids. |
| `meta.underlay` | child diagram | `"setup-map"` → the parent is drawn ghosted (opacity .22, no pointer events) beneath the child, same toggle state, same geometry code. Optional. |
| `meta.showPrompts` | diagram | `true` → draw the literal index prompt as a small dim line under each step node's label (live and snapshot). |
| `node.step` | node | A step id from `steps.json` (`"A5"`, `"C8.key"`). Unique per diagram. The node keeps its own concise `label`. |
| `edge.rail` | edge | `true` → this pipe is part of the question-to-question trajectory in the `wizard` diagram (drawn as a normal Mario pipe). |

Captions for the overlay (phase 1, no per-question nodes) live in `meta.replay.captions = {"A5": "How will the box get online after the install?", …}`; a caption for an unknown id fails the verifier.

### 3.2 Generated files

`docs/replays/steps.json` (sort_keys, indent 2, like `_dump`):

```json
{"version": 1,
 "scanned": {"dash": "<sha256>", "tools/resolve_flake.sh": "<sha256>", "…": "…"},
 "steps": {
   "A5": {"phase": "A", "kind": "ask", "hidden": false, "repeatable": false, "redact": null,
          "prompt": "pick a number 1-4 [1]: ", "prompt_re": "pick a number 1-4 \\[1\\]: $",
          "sources": [{"file": "tools/resolve_flake.sh", "line": 106, "call": "ask"}],
          "src_hash": "<sha256 of the normalised source span marker→prompt>"},
   "A7": {"phase": "A", "kind": "ask_secret", "hidden": true, "…": "…"},
   "B":  {"phase": "B", "kind": "info", "…": "…"}}}
```

`docs/replays/wizard/<config>.cast` — asciicast v3: header `{"version":3,"term":{"cols":120,"rows":32},"idle_time_limit":2,"title":"wizard <config>", "env":{"SHELL":"…"}}`, then `[dt,"o",text]`, `[dt,"m","<step id>"]`, `[dt,"x","0"]`. `<config>` = `method-cable_net-0a_reach-tailscale` (file-safe form of the hash key `method=cable;net=0a;reach=tailscale`; `net` omitted for `vm`).

`docs/replays/wizard/<config>.meta.json` — provenance + audit: `run_id`, `recorded_at`, `complete`, `provisional` (dirty/forced run), `recorder` (asciinema version, window, idle cap), `repos` (name/branch/commit/dirty — reusing `run_entry`'s provenance), `pins`, `state_hash`, `steps_index_hash`, `steps_src` ({id: src_hash at record time}), `markers` ([{id,t}]), `redaction` (rules_version, counts per rule), `squashed` ({kept_head, kept_tail, dropped}), `sha256`, `sha256_raw`.

`docs/replays/wizard/index.json` — `{"configs": {"<config>": {file, meta, recorded_at, commit, complete, provisional, stale_steps: [...]}}, "rules_version": n}`; the page fetches this once and then only the cast for the active configuration.

### 3.3 URL hash

Two **reserved, non-toggle** keys: `at=<stepId>` (resolves to that step's first marker time once the cast loads — stable across re-recordings) and `t=<seconds, 1 decimal>` (exact, on the *adjusted* timeline, idle gaps capped at 2 s like `asciinema play`). `t` wins if both are present. Written on scrub release / marker jump / pause (not per frame). Example: `flow.html#setup-map;method=cable;net=0a;reach=tailscale;at=C8.key`. Today `writeHash()` (`flow.js:648`) emits only declared toggle ids and `openDiagram()` (`flow.js:671`) copies every hash key into `S.toggle`; both get an explicit reserved-key path.

## 4. Recording pipeline (explicit commands, no defaults)

**4.1 Record** — one complete from-scratch run (req 159), on the laptop, target netbooted as today:

```
cd ~/git/personal/selfprivacy/dev-dashboard
./dash record-wizard --cast media/replays/raw/$(date -u +%Y%m%dT%H%M%SZ).cast --subnet 192.168.1 [--expert-mode]
```

`record-wizard` execs
`asciinema rec -q --overwrite --window-size 120x32 --idle-time-limit 2 --capture-env SHELL --title 'wizard' -c './dash find-target --subnet 192.168.1 [--expert-mode]' <cast>`
(binary from `$ASCIINEMA_BIN`, else the pinned nix store path; version written to the sidecar). It **never** passes `-I`/`--capture-input` (that would store keystrokes, including hidden passwords). The whole chain lands in one pty because `find-target` hands off with `subprocess.run(["bash", _rf], …)` (`dash:1620`), every bash prompt reads `/dev/tty` (`resolve_flake.sh:21-22`, `add-cloudflare.sh:71`, `finish_box_setup.sh:42`), `./dash run` re-prints each line of the install child (`dash:1224-1228`), and the guided finish runs on the same terminal (`dash:1301` onward). Verified consequence: nix sees a **pipe**, so no progress-bar redraws reach the cast (a raw-pty recording of `nixos-anywhere` would be ~2.8 MB of `ESC[K` redraws; the verifier rejects such casts).

**Prerequisite:** `--expert-mode` is not threaded through `find-target` today (`requirements.md` req 164 calls it a follow-up), so only `reach=tailscale` can be recorded from scratch. Step 0 of the plan adds `./dash find-target --expert-mode` → env `SP_EXPERT_MODE=1` → `resolve_flake.sh:93` appends `--expert-mode` to the `add-cloudflare.sh --plan` call.

The netboot server terminal (`sudo bash ~/netboot/start-netboot-server.sh`) is a second terminal and is not recorded. USB installs (`tools/e2e_install_usb.sh`, prompts at lines 74/96/107) get the same wrapper later via `./dash record-run --cast … install.usb …` (follow-up configuration).

**4.2 Import** (deterministic, idempotent):

```
python3 tools/replay_import.py --raw media/replays/raw/<ts>.cast --steps docs/replays/steps.json \
        --out-dir docs/replays/wizard --denylist state/redact.local
```

1. Parse v3 (v2 accepted and normalised). Stream-scan all `o` payloads concatenated (a marker can straddle two events), cut `\e]9999;sp-step=<id>[;r=…]\e\` out and insert `[dt,"m","<id>"]`; fold `sp-var` markers (`SETUP`, `PUBLIC_METHOD`, `PUBLIC_CF_NAMED`, `RUN_ID`) into the sidecar and derive the **configuration key from the run itself** (one table: `install.lan-setup-0a..0d`→cable/0a..0d, `lan-setup-1/2`→wifi/w1/w2, `usb-0a/0b/0c`→usb/ua/ub/uc, `vm-local`→vm; `tailscale`→tailscale, `cloudflare`→cloudflare, `ipv6`→ipv6, `router`→portfwd, `none`→onion; ngrok/pinggy/localtunnel have no diagram option → stored, warned, never selected).
2. **Redact**, in fixed order, with a `rules_version` stamped in the sidecar: R1 `tskey-[a-z]+-…`→`tskey-auth-<REDACTED>`; R2 64-hex → `<API-TOKEN>` (`print_app_cmd` prints the box token in clear, `add-cloudflare.sh:346-352`); R3 Cloudflare/ngrok/DuckDNS tokens; R4 MAC → keep OUI, mask host; R5 public IPv4/IPv6 → `<public-ip>`, private IPv4 last octet masked except the fixed netboot subnet `192.168.100.x`; R6 provider hostnames (`*.tail….ts.net`, `*.trycloudflare.com`, `*.ngrok-free.app`, `*.pinggy.link`, `*.loca.lt`, `*.onion`) → placeholders; R7 **step-aware echo replacement**: for steps flagged `redact=<placeholder>` in the index (SSID, typed domain, flake path, LAN IP, localtunnel prefix) the echoed answer is replaced *everywhere* in the cast (so later echoes such as `✓ wifi '<ssid>' is in range` stay consistent); R8 `/home/<user>`→`~`, hostname → `<laptop>`; R9 local denylist `state/redact.local` (one literal per line: personal domain, tailnet id, public IP, SSID; `state/` is git-ignored); R10 entropy guard: any ≥32-char token with Shannon entropy > 4.0 bits/char that is not a nix store hash or git sha → **refuse to write** ("review needed at marker X"). **Hidden-input assertion:** for `hidden: true` steps the text between prompt and `\r\n` must be empty, else refuse.
3. **Squash phase B**: between markers `B` and `B.verified` keep the first 30 and last 60 `o` events and insert one labelled elision event `… [N output lines squashed — full log in logs/<run_id>.log] …` whose interval preserves the real elapsed time (same precedent as `trim_log`, `dash:1333`). Counts go to the sidecar; the UI labels the span "squashed".
4. Refuse to write into `docs/` unless the run is **complete** (first marker = route start, last = `END`, exit `0`); partial runs go to `media/replays/partial/` and are never shown (req 159).
5. Write cast + sidecar, regenerate `index.json`, print the substitution table for a human eyeball review (`asciinema convert <cast> - | less`).

**4.3 Size budget** (measured from real install logs: ~1,200 lines, ~100 B/line, 1.18× JSON overhead): a full run is ~150–200 KB as text, ~50 KB gzipped, before squashing. Hard cap 256 KB per cast (verifier), fixed 120×32 geometry, `idle_time_limit` is a player hint (it does not shrink the file; the player implements the cap itself).

## 5. Marker instrumentation

Helper in `tools/prompt_lib.sh` (already sourced by `resolve_flake.sh:18` and `add-cloudflare.sh:29`; `finish_box_setup.sh` and both `e2e_install_*.sh` gain a `. prompt_lib.sh` line):

```bash
sp_step(){ printf '\033]9999;sp-step=%s%s\033\\' "$1" "${2:+;$2}" >&2 2>/dev/null || true; }   # sp_step A6 redact=wifi-name
sp_var(){  printf '\033]9999;sp-var=%s=%s\033\\' "$1" "$2" >&2 2>/dev/null || true; }
```

Rules (each one was found the hard way in the experiments): **stderr only** (stdout of `add-cloudflare.sh --plan` is `eval`'d by `resolve_flake.sh:93`; a marker on stdout breaks the plan), **never a `{ …; } 2>/dev/null` group** (that silently drops the marker), **OSC number 9999**, not 1337 (iTerm2's namespace, acted on by kitty/VTE), **record the wizard directly** (tmux swallows unknown OSCs), one marker **immediately before the re-ask loop** of each question (an invalid answer re-asks inside the same step). Python twin in `dash`: `sp_step(id, redact=None)` writing the same bytes to `sys.stderr` with a flush. Markers are always on (invisible); the log writer strips OSC 9999 so `logs/<run_id>.log` stays as today.

Step ids reuse `setup-flow.md`'s A1–A8 / C1–C8 numbering (decision: retire the `cli-flow.puml` `[1.Y.A]` numbering in docs over time):

## 6. The verifier (`tools/replay_verify.py`) and where it runs

Exit 1 on any FAIL, one line per check (`file:line` / `config:step`), `--json` for CI annotations, `--strict` escalates staleness, `--ci` skips the local denylist.

| # | Check | Fails when |
|---|---|---|
| V1 | step index fresh | regenerated `steps.json` ≠ committed (same guarantee the `.svg` snapshots have) |
| V2 | ids known | a diagram `node.step`, a route step, a caption or a cast marker names an id not in the index; duplicate ids in scripts |
| V3 | coverage | an `ask`/`ask_secret` step in the index is on no route/node of the `wizard` flow diagrams ("a new CLI question is not on any diagram") |
| V4 | paths align with the CLI | for **every valid toggle combination** (same `optionsWhen` logic as `gen_flow_svg.py:251`): the route's waypoints are connected by edges drawn in that state, in order; in `wizard` exactly one simple rail from start to `END` through every visible step node; no orphans/branches |
| V5 | literal quotes | any backtick-quoted substring in a concise label occurs verbatim in that step's real prompt |
| V6 | cast shape | version 3, term 120×32, no `i` events, size ≤ 256 KB, only whitelisted sequence classes (SGR, EL, CR, LF, BS, TAB, OSC-free), sidecar sha matches, config is a legal toggle combination, file name = config |
| V7 | marker walk | every `m` label ∈ index; the walk is forward along the route except documented back-jumps inside phase A (`<` navigation) and `repeatable` ids; first = start, last = `END`, `complete: true` |
| V8 | prompt text | the output after each `ask` marker matches the index `prompt_re` — the literal tie between recording and code |
| V9 | secrets | R1–R8 patterns zero hits, denylist zero (local), entropy zero, hidden-input assertion holds |
| V10 | idempotent | `normalise(cast) == cast` byte-for-byte (proves the committed file went through the current rules) |
| V11 | staleness | `meta.steps_src[id] ≠ index.steps[id].src_hash` → `stale_steps` written to `index.json` (WARN; FAIL under `--strict`); `provisional` for dirty/forced runs |
| V12 | renderer parity | Python `Term` vs JS `Term` on a committed self-test cast (Python here; JS via `tools/scrub_flow.py` in CI) |

Negative fixtures ship with it (`tests/replay_fixtures/`: injected `tskey-auth-X`, unknown step, two rail edges, altered A5 prompt) and must each exit 1.

**Hook** (`.githooks/pre-commit`): widen the trigger at line 7 (today only `docs/*.puml|py` and `render-diagrams.sh`; a `docs/diagrams/*.json`-only change re-renders nothing, and line 10 stages `docs/*.svg` but never `docs/diagrams/*.svg` — two existing gaps) to also match `docs/diagrams/**.json`, `docs/replays/**`, the six scripts, `dash`, `flow.js`, `replay.js`, `tools/replay_*.py`; then run `replay_index.py --write` → `replay_verify.py --fix-index` (abort on FAIL) → `render-diagrams.sh` (fast path `gen_flow_svg.py` only when just JSON/casts changed) → stage `docs/*.svg docs/diagrams/*.svg docs/replays/steps.json docs/replays/wizard/index.json`. Refuse any staged file under `media/`.

**CI**: `diagrams.yml` gets the same paths plus a verifier step before rendering, and on PRs an exact `git diff --exit-code` on snapshots/index instead of the non-empty check; `pages.yml` runs `replay_verify.py --ci` before uploading (a leaking or drifting cast is never deployed). Optional weekly `--strict` job that opens an issue listing stale configurations with their re-record command.

## 7. UI

**Player box.** A new `<g id="player">` after `<g id="nodes">` inside `#viewport` (`flow.html:146-148`) so it pans/zooms with the diagram and sits on top. World size 520×300: title bar (`A5 · pick the network setup · t=12.3s · cable/0a/tailscale · rec <date> @ <sha7>` + `stale`/`provisional`/`squashed` badges), then the last rows of a 120×32 terminal as one `<text>` per row with `<tspan>` per colour run (`31`→red, `32`→green, `33`→amber, `36`→blue, `90`→dim, bold → 600). **Pure SVG text, no `foreignObject`**, so the live view, Playwright and the static snapshot render the same thing. An anchor dot + stem marks the exact trajectory point. Placeholder state (dashed): `No real recording yet for Install=<label> · Network=<label> · Reach=<label>.` + the record command. A `#castbar` under `#togglebar`: ▶/⏸, ⏮/⏭ marker, speed 1×/2×/4×, "pause on prompts", provenance line, `T` transcript panel (full literal transcript, current line highlighted, copy).

**Terminal model** (`Term(cols, rows)` in `replay.js`, byte-identical twin in `tools/replay_lib.py`): a *stateful stream parser* fed events in order (sequences straddle events): grid with cursor; `\n` (scroll on last row), `\r`, `\b` (cursor-left, **not** delete — `mke2fs` emits `\b…\b`), TAB; `ESC[K` 0/1/2; SGR with `;` and `:` separated params covering 0,1,2,22,30-37,39,90-97 and 38/48 with 5/2 sub-params (colour approximated, never mis-split — all seen in real logs); OSC consumed to BEL/ST; any other CSI/ESC ignored; counts code points. ~120 lines each.

**Trajectory.** `trajectory()` keeps the waypoints of `meta.replay.route` whose `showWhen` matches and whose node/edge is drawn in the current toggle state; `at` → a horizontal chord across `rbox(node)` (so a dwell with many questions is scrubbable inside the box); `along` → `dedupe(pipePoly(boxOf[from], boxOf[to], e))` (`flow.js:221`), reversed with `rev`. In `wizard`, the rail pipes (`edge.rail`) in start→end order play the same role. `midOfPoly` (`flow.js:209`) generalises to `pointAtFrac(poly, f)`; a `projectOnPoly(poly, p, sPrev)` picks the nearest segment with a continuity rule (prefer candidates near the current arc position — back-navigation makes the track overlap itself).

**Position ↔ time ("perfect timing").** Time base = the cast's **adjusted timeline** (cumulative `dt`, each gap capped at `idle_time_limit`, identical to `asciinema play`/`agg`). Each waypoint `i` gets a stop `(s_i, t_i)`: `s_i` = its arc position, `t_i` = the time of the first `m` event of its first present step. Between stops the map is piecewise-linear and monotone in both directions, so dragging and autoplay are exact inverses; waypoints with no marker in this cast collapse (no wifi questions in a `0a` run). Frames are rebuilt from the keyframe at the previous marker, so **reverse is exact**, not approximate.

**Drag / play.** `pointerdown` on `#player` is checked **before** node hit-testing (`flow.js:937`) → `S.mode="scrub"` + pointer capture; `pointermove` projects → `t` → `renderPlayer(t)` only (never the full `render()`, which wipes and redraws everything); `pointerup` snaps to the nearest stop within 14 world px and writes the hash. Autoplay via `requestAnimationFrame`, pauses 1.2 s at every `ask` prompt, stops at `END`; `[`/`]` previous/next marker, `←/→` ±1 s, Space toggles. Scrubbing never calls `markDirty`. The node whose span contains `t` gets `.active`; the travelled rail is drawn brighter.

**Concise vs literal.** `node.label` = the guiding text (FR26 plain language, `nodeType: "action"` for questions, `"info"` for milestones). Under it a small dim monospace line with the index prompt (`meta.showPrompts`), the full prompt + `file:line` + recorded answer in the hover tooltip (`#tooltip`), click → jump the player there. The player frame always shows the real bytes.

**Toggle inheritance** (`wizard` child). `openDiagram(id, toggleState)` (`flow.js:671`) already accepts a state but only `init` (`flow.js:1156`) passes one; the drill-down and breadcrumb calls pass none, and `writeHash` strips undeclared ids. Change: when the target's `meta.inheritToggles` is true, take `meta.toggles` from the parent JSON (one definition, no copy), pass `S.toggle` on drill-down and breadcrumb, render the parent's toggle bar. ~21 lines in `flow.js`, ~12 in `gen_flow_svg.py` (`default_state`, `when_ok` with inherited toggles). Verified live today: double-clicking from `usb/ua/onion` lands on defaults.

**Static snapshot** (`docs/gen_flow_svg.py`): `render_player()` after the node loop: default toggle state → config → cast if present → Python `Term` fed to the first route marker → the same rect+text group at the route start; else the placeholder. Optional `render_underlay()` for `wizard`. Deterministic (inputs are all committed); run twice and `cmp`.

**Verification harness** (FR67): `./dash serve 8099` then `python3 tools/shot_flow.py 'setup-map;method=cable;net=0a;reach=tailscale;at=A5' /tmp/a5.png` — the hash is passed verbatim and `#fit` is clicked, so any scrub state is one screenshot away. `tools/scrub_flow.py` drives a real Playwright drag (`mouse.down` on `#player`, `move` along the pipe, `up`), asserts the hash ends with the expected `at=`, and compares `window.__flow.screenRows()` with the Python `Term` at every marker (V12).

## 9. Proposed requirements text (FR89+, ready to paste after FR88)

- **FR89. Real recordings only.** Every frame the player shows comes from a committed asciicast of one complete from-scratch run (req 159) of the real scripts. A configuration without a recording shows a dashed placeholder naming the configuration and the exact record command. Partial, resumed or hand-patched runs are never imported into `docs/`.
- **FR90. Scripts emit step markers.** Each prompt of the install wizard is preceded by `sp_step <id>` (OSC 9999 on stderr, invisible in terminals, never on stdout). Ids follow `setup-flow.md` (A1–A8, C0–C8, U1–U3, B, END, dotted sub-ids). The importer converts them into native asciicast marker events.
- **FR91. Generated step index is the CLI interface.** `docs/replays/steps.json` is produced by scanning the scripts (id → file:line, literal prompt, hidden/redact flags, source hash) and must be byte-equal to the committed file on every commit. Diagrams bind to questions by id only; the literal prompt is never copied into diagram JSON.
- **FR92. Verifier in hook and CI.** `tools/replay_verify.py` fails the commit/CI on: unknown or uncovered step ids, a route/rail that is not connected by drawn edges in some toggle state, a cast whose marker walk or prompt text disagrees with the scripts, secrets (patterns, denylist, entropy, hidden-input echo), oversized or malformed casts, a stale index, non-idempotent normalisation, renderer parity failure. The hook also triggers on `docs/diagrams/*.json` changes and stages `docs/diagrams/*.svg` (closing two existing gaps).
- **FR93. Redaction gate.** Raw casts live only under git-ignored `media/`; committed casts are normalised and redacted (R1–R10 + step-aware echo replacement + local denylist) and the verifier re-scans them. Keystrokes are never captured (`-I` forbidden).
- **FR94. Trajectory = the diagram's own pipes.** `meta.replay.route` lists waypoints (`at` node / `along` edge) with the steps that happen there and `showWhen`; the polyline is derived from the same `rbox`/`pipePoly` geometry at render time (overlay on `setup-map`; rail pipes in `wizard`). No coordinates are stored for the player.
- **FR95. Drag-to-scrub with exact timing.** Position ↔ time is piecewise-linear between marker stops on the adjusted timeline (idle gaps capped at 2 s); dragging back rewinds exactly (frames rebuilt from keyframes), forward fast-forwards; autoplay pauses at every prompt. Scrubbing never dirties the diagram.
- **FR96. Hash state for verification.** Reserved keys `at=<step>` and `t=<sec>` (never toggles) make any scrub state reproducible by `tools/shot_flow.py`; `tools/scrub_flow.py` drives a real drag and checks JS/Python renderer parity.
- **FR97. Concise label, literal tie.** A step node keeps its hand-written guiding label plus `step`; the literal prompt (from the index) is shown small under it and in the hover with `file:line` and the recorded answer. Backtick-quoted text in a label must occur in the real prompt.
- **FR98. Per-step staleness, honestly shown.** A recording whose step source hash no longer matches is flagged `stale` per step (UI badge, index entry, re-record command printed); CI `--strict` fails on stale recordings on `main`. Dirty or forced runs are `provisional`.
- **FR99. Child diagrams may inherit toggles.** `meta.inheritToggles: true` uses the parent's toggle definition and state (hash unchanged); optional `meta.underlay` draws the parent ghosted beneath so a drill-down is authored along the parent's pipes.
- **FR100. Snapshot parity for the player.** `gen_flow_svg.py` draws the player at the route start with the first real frame of the default configuration (or the placeholder) using the Python twin of the terminal model; pure SVG text, deterministic.

## 10. Risks and open decisions (with a recommendation each)

1. **Staleness strictness.** Block locally on prompt drift, or flag + fail only in CI? *Recommend:* hook blocks structural misalignment and secrets; prompt drift is auto-flagged and visible; CI `--strict` on PRs/main fails until a fresh recording is imported. Blocking every local commit would demand a 30-minute hardware run per wording tweak.
2. **Overlay first vs `wizard` first.** *Recommend:* overlay first (phases 5–8), `wizard` in phase 9 — the engine is shared, and the overlay gives the moving box on the pipes with no new diagram to lay out. If the per-question view turns out to be what you look at most, swap 5 and 9.
3. **Recording location.** `docs/replays/` in dev-dashboard (Pages same-origin, hook-gated) vs the testresults repo. *Recommend:* dev-dashboard; link the run via `run_id` to `results.jsonl`.
4. **Private-IP masking depth.** Last octet (keeps `192.168.1.x` readable) vs full. *Recommend:* last octet, netboot subnet unmasked; one-line rule change + `rules_version` bump if you want more.
5. **Step-id vocabulary.** `setup-flow.md` ids (chosen) vs `cli-flow.puml` numbering. *Recommend:* adopt the former everywhere; update `cli-flow.puml` labels in phase 10.
6. **Missing reach options.** ngrok/pinggy/localtunnel can be recorded but have no `setup-map` option. *Recommend:* keep them unselectable with a verifier WARN until the diagram grows those routes.
7. **VM method.** No `find-target` chain (`install.vm-local` runs `build-and-run.sh`). *Recommend:* a permanent "VM install has no wizard" note instead of the generic placeholder.
8. **Hidden auth-key prompt.** Switch `add-cloudflare.sh:473` to `ask_secret`. *Recommend:* yes (raw casts then never hold a key; the recording shows nothing typed, which is also what a password field looks like).
9. **Fully automatic re-recording.** Only the VM path could ever be re-run by the self-hosted runner end-to-end; netboot/USB need a human. *Recommend:* out of scope now; the stale flags + weekly issue keep "always updated" actionable.
10. **Two terminal models (Python/JS) can drift.** Mitigated by V12 on a committed self-test cast (same approach as `gen_flow_svg.py` vs `flow.js`).
11. **Idle cap distorts durations** (a 5-minute reboot plays in 2 s). The title bar shows both `real 7m12s` and the cap.
12. **Hook latency.** Verifier < 1 s; the plantuml render is the slow part and is skipped on JSON/cast-only commits.

## 12. Evidence (from the verification runs, scratchpad experiments)

- asciinema 3.2.1 writes v3 (relative `dt`, `o`/`m`/`x` events); `\e]9999;sp-step=A3\e\` survives verbatim inside `o` events, is stripped by `convert … .txt`, can straddle two events; `agg --select markers` consumes native `m` events. OSC 1337 is recognised by kitty/VTE/iTerm2 — not used. tmux swallows unknown OSCs — never record through it.
- Escape-sequence survey of `dash` and all six scripts: SGR only (`\e[0m/1m/31m-36m/90m`), no cursor movement; real logs additionally contain `\r` (`dd status=progress`), `\b` (`mke2fs`), `ESC[K` + multi-param SGR with `;`/`:` (nix on a tty) — hence the stateful stream parser and the whitelist gate.
- Size: real phase-B logs ~1,218 lines × ~102 B; cast overhead 1.18× → ~150–200 KB per full run via the dash line pipe; a raw-pty `nixos-anywhere` recording ≈ 2.6–2.9 MB of redraws. `--idle-time-limit` does not change file size.
- GIF: a faithful 73 s wizard mock → 64 KB cast / 10 KB gzipped vs 45 MB of per-step GIFs; `agg` renders headless with system fonts, byte-identical on one machine.
- Scrub: `foreignObject` and pure SVG text both render inside the zoomed `#viewport`; Playwright `mouse.down/move/up` reaches the pointer-captured svg; a `scrub=` hash key is read at boot but stripped by today's `writeHash` — reserved keys needed.
- Toggle inheritance: live test from `#setup-map;method=usb;net=ua;reach=onion` → double-click → child at defaults; breadcrumb back → parent reset to defaults. `openDiagram(id, toggleState)` is the existing hook.
- Instrumentation: a marker on stdout breaks the `eval`'d plan (`'\E]1337': command not found`, `DOMAIN` lost); a `{ …; } 2>/dev/null` group drops it silently; `prompt_lib.sh` reaches only two of the five scripts today.
